# Lint Room: a second pair of eyes

An original local CSS review desk, built around the exact `tooling/css-checker.ts` exported parser function used by the optional CLI. A native textarea preserves editable text, caret and selection. Checking is explicit, either through Check CSS or Control + Enter inside the editor. Edits mark diagnostics stale and disable their source-selection buttons until checked again.

Six useful studies cover the radius typo, transition scope, intentional motion, literal comments/content, a genuinely unfinished grammar block and bounded 30-note output. Selecting a diagnostic focuses and selects its actual UTF-16 span. A clean result means only the three configured checks passed. The grammar accepts some semantically invalid declarations, such as an empty value; this is not a semantic property/value validator, accessibility audit or browser compatibility tool.

The local file control accepts one CSS file up to 256,000 bytes and 64,000 UTF-16 code units, decodes UTF-8 strictly, and leaves existing edits intact on failure. Concurrent reads use a generation guard; a stale file result cannot replace the latest selection. Nothing is uploaded. Downloads contain the local editor text or an explicitly saved CLI receipt. No arbitrary CSS is applied to the page.

The command section is visibly labeled **PRECOMPUTED CLI FIXTURE**. Its receipts were generated by the actual distributed Node binary; a public webpage cannot execute that command. The shown receipt stays associated with its named fixture when the editable document changes. No live shell or Claude client session is simulated.

## Validation and scope

Native T3 Chromium/Electron validation covered six states at 320×700, 390×844, 768×1024, 844×390 and 1440×900: 30 cases. Native controls and the actual inner file input met the library's 44px policy, fields used 16px text and horizontal page overflow was zero. The editor keeps native internal horizontal scrolling for long CSS lines. This is desktop CSS viewport validation, not physical phones, Safari or assistive technology.

Browser checks verify exact typo selection, stale notes after an edit, an explicit keyboard check, Unicode UTF-16 coordinates, preserved text on invalid UTF-8/oversized/unsupported files, stale file-read rejection, quiet mode, a solid plate with no backdrop filter, cancellation and zero pending tour timers. Locally constructed native File objects exercise the browser APIs; the OS file chooser was not driven. OS reduced motion was observed false; it was not changed. No RAF runner or parser polling is installed.

The actual standalone distributed CLI was exercised with 25 cases: six stdin/file fixture pairs, lexical root boundaries, interior symlinks, missing files, invalid UTF-8, source cap, unsupported extension, advisory hook findings/outside-root/unsupported/malformed envelopes, help, version and a copied standalone binary without node_modules. Assertions verify exit codes and parser agreement. Hook output contains only the advisory envelope, excludes untrusted source/root/tool response and remains exit 0. This is a local process contract, not verified Claude Code hook delivery or an adversarial filesystem sandbox. Native Windows is unverified.

## Timing and payload

The local **0.53.0-preview.1** Node artifact is 78,919 bytes / 28,895 bytes gzip; notices add 4,535 bytes. It bundles the optional parser, unlike the zero-dependency material entrypoints. The standalone browser study JS is 86.76kB / 30.57kB gzip, including the parser and saved fixture receipts. These are payload measurements, not page loading-time claims.

On this Linux Node24 session, 20 new-process checks had median 54.667ms and p95 63.744ms including startup, stdin decoding, parse, JSON and output. Shared-checker CPU alone over 100 batches of 500 short 92-character calls had median 12.672ms / batch and p95 20.448ms. Fifteen near-cap 63,954-character calls had median 15.556ms and p95 21.884ms after three warmups. These scopes exclude DOM/paint/network. An earlier v0.30 native browser check at that same input size took 21.5ms including diagnostic DOM creation, excluded painting, and displayed the 30-note truncation message. It is one observation, not a cross-environment comparison or speedup claim.

## Distinct independent feature

Add an optional host action-lifecycle controller for real application buttons, for example `attachGlassAction(button, { run, statusElement, labels, onState })`, exposing a typed `invoke()` and `cancel()/reset()/destroy()` lifecycle. Navigation CTAs remain anchors and must not be intercepted or delayed. The inspiration supports clear intent; the lifecycle proposal is our independent extension for web tools and AI apps, not behavior claimed to have been extracted from hidden sign-up flows.

A real action should have explicit idle, pending, submitted, success, error, and cancelled outcomes as appropriate. Prevent repeated activation while a request is pending. Require the host to supply a meaningful result before showing success; a callback resolving without confirmation means submitted, not that a server executed or saved something. Pass an AbortSignal to cooperative host work and ignore stale generations after reset/destruction. Aborting a client request does not undo a server-side operation; host applications own authorization, idempotency, confirmation, and receipts.

Use a native `type="button"` for the initial standalone API. A form integration must listen to normal validated submission, preserve the submitter and its data, and call the controller only after native/client validation; do not use `form.submit()` to bypass the submit event and constraints. Do not silently attach a competing submit handler or prevent existing native navigation. Preserve labels, dimensions, authored attributes and focus behavior. Keep icon/spinner decoration hidden from assistive technology and announce concise status text in a separate appropriately scoped status region.

`aria-disabled` alone does not suppress activation; guard the actual action path if maintaining focusability while pending. Native `disabled` also changes focus/form participation, so choose and document a consistent policy. Use `aria-busy` on the actual changing region without suppressing important error/status announcements indefinitely. Retry should be explicit and only offered for a host-confirmed retryable operation, never automatic for payments or mutating requests.

The existing micro-motion and finite-feedback modules can decorate state changes; this feature adds correctness and useful host state, not another entrance animation preset. An original showcase can create a small local export with a real Blob download, inspect an explicitly simulated submission, and demonstrate a controlled rejected operation with retry. Each label must describe what truly happened; a local preview should not imply AI generation, remote storage, or public publishing.

## Primary references and performance

- https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/button documents native activation and button/form behavior.
- https://developer.mozilla.org/en-US/docs/Web/API/HTMLFormElement/requestSubmit explains why requestSubmit performs validation and dispatches submit while submit alone bypasses those steps.
- https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Attributes/aria-disabled explains the distinction between semantic disabled state and actual event suppression/focus behavior.
- https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Attributes/aria-busy defines the changing-content state; it is not proof of completion and is not a substitute for a status message.
- https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html describes exposing progress/results/errors without stealing focus.
- https://developer.mozilla.org/en-US/docs/Web/API/AbortController documents cancellation of cooperative client operations, not rollback of remote work.

Use one operation generation, one bounded pending promise/controller, and at most a finite reset timer. No polling, idle RAF, artificial minimum waiting time, or repeated automatic retry. Any busy decoration must stop immediately on settle/cancel/destruction and respect reduced motion. Reserve icon space and keep action dimensions stable to limit layout shifts; avoid rendering a backdrop filter on each nested icon/state. Test rapid double activation, keyboard activation, preexisting disabled state, resolved-without-receipt behavior, rejected work, cancellation with a late result, reset while pending, destroy while pending, native validation, and focus preservation. Benchmark actual controller work separately from artificial host delays. Gallery inclusion does not establish conversion improvements.

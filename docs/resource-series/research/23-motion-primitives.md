# Resource 23: Motion-Primitives

Reviewed 2026-10-11 with Exa and native T3 preview. Two live public components, their APIs, an additional disclosure example, the exact repository license, and primary sizing/layout references were inspected. No CLI install, copied source, external form submission or republished preview media was used. License discovery returned four candidates and the author-owned file was verified.

## Two actual public interactions

- https://motion-primitives.com/docs/transition-panel exposes activeIndex, transition and enter/center/exit variants. Native activation of Art changed the tab-style content from one heading/body to another and left focus on Art. The separate card's Next button changed Brand to Product; after native active-frame settling the visible panel grew from its previously observed 130 px height to 158 px. Intermediate old/new nodes had different opacity, translation and blur values; they were removed/settled after the transition. These observations establish a real content/size transition, not a guarantee of semantic tab behavior or complete screen-reader handling.
- https://motion-primitives.com/docs/text-morph exposes string children and an authored semantic tag. Native activation of Continue changed its label to Confirm. Shared-character spans moved during the transition; the settled result used a whole-word `aria-label="Confirm"` with each decorative letter marked `aria-hidden="true"`. This is a useful accessibility pattern when splitting text. The separate editable-text example initially contained Craft, but its input had a placeholder without a native label or aria-label in the sampled DOM; do not reproduce that omission.

https://motion-primitives.com/docs/disclosure additionally documents host-controlled open/onOpenChange and custom variants. That visibility contract overlaps planned semantic disclosure/navigation widgets; it is not a reason to duplicate them. The public library is built around React, Motion and Tailwind conventions; the useful behavior can be implemented independently with native controls and existing library motion utilities.

## Distinct independent feature

Add an optional intrinsic-size transition controller around an authored shell/content pair, for example `attachGlassSize(shell, content, { duration, reducedMotion })` exposing a bounded `transition(updateContent)`, `refresh()`, `cancel()` and `destroy()`. The host commits real content/state; the helper animates the shell's measured block size and returns it to natural sizing at rest. A scoped first release can support block-axis changes in horizontal writing modes rather than pretend arbitrary transformed/writing-mode layouts work automatically.

Take a before measurement, run the host's synchronous update once, take the new natural-content measurement, and animate between explicit sizes with finite completion/cancellation. Rapid updates must sample current presentation or cancel/retarget coherently; do not queue every intermediate host state. Pending outcomes should distinguish completed from cancelled. At rest, remove only owned fixed-size declarations so future text, font and image changes can flow naturally. An explicit refresh can handle asynchronous renderer commits or later asset changes; do not imply the helper can know when every React/Vue update has committed.

Keep one actual content tree. Do not clone inputs/buttons, duplicate IDs, move focus just to animate, scale text as a shortcut, or hide outgoing focusable content by opacity alone. The host owns selection, expanded/hidden/inert state, routing and focus when replacing/removing a focused subtree. A size-only enhancement must not turn ordinary content into a fake dialog or trap keyboard navigation. Avoid blindly clipping a newly focused control while a shell grows; visible native focus and selection must remain usable throughout.

Reduced-motion requests snap directly to current natural size. Cancellation, hidden documents, detachment and destruction stop active work and restore authored size/style priorities. If observing content changes, observe the inner natural content and coalesce notifications; never observe and continually rewrite the same measured shell into a resize feedback loop. Do not animate every viewport/keyboard resize by default, or clamp essential content to a decorative maximum height. Size overflow and scrolling remain authored layout decisions.

This differs from one-element entrance/press motion, document bitmap view transitions (source 09), static composition (source 04), and numeric display changes (source 22): it adapts a real panel's geometry to different content sizes. An original showcase can use a short/long settings panel, a plan summary with expanded steps and a locally validated form message, retaining real controls and visible focus. A bounded tour can show three state changes without an unattended loop.

## Primary references and performance

- https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/interpolate-size is explicitly limited/experimental. It permits a numeric endpoint to interpolate with an intrinsic keyword; it does not animate arbitrary auto-to-auto content changes simply because the property is enabled. Feature-detect and scope any enhancement rather than set it globally on :root.
- https://developer.mozilla.org/en-US/docs/Web/API/ResizeObserver documents box measurements and resize-loop risks. A browser's loop guard does not fix a cyclic controller.
- https://developer.mozilla.org/en-US/docs/Web/API/Element/getBoundingClientRect documents viewport-relative border-box geometry and scroll effects. Do not confuse natural content dimensions with a transformed visual box.
- https://developer.mozilla.org/en-US/docs/Web/API/Element/animate and https://developer.mozilla.org/en-US/docs/Web/API/Animation/finished document finite native animations and lifecycle promises. Handle cancellation/rejected finish promises; do not remove host content merely because any unrelated animation ended.
- https://motion.dev/docs/react-layout-animations is the upstream Motion explanation of layout transforms, shared layout and scale correction. Its transform performance claims apply to its implementation, not automatically to our block-size tween.

Actual block-size animation can trigger layout and paint every frame, especially with translucent surfaces and neighboring content. A numeric size tween is not a compositor-only/free animation. Batch necessary before/after reads, avoid per-frame subtree measurement, use finite duration, and restrict concurrent panels. Prefer immediate sizing or translation-only presentation for very large/repeated collections. No idle RAF or permanent fixed height is needed. Benchmark scripting, layout/paint and active/rest behavior with realistic text and one glass surface, compared with an immediate update. Test identical sizes, long translations, async images/fonts, rapid retargeting, authored min/max size, focused descendants, scroll containers, reduced motion, detach/destroy and observer recursion. Do not sell measured demo speed as universal performance.

# UI library selection for the redesign

Reviewed on 10 October 2026. The request explicitly named **GitLab**, so this review checks that hosting rather than silently substituting GitHub projects. Exa returned 85 search results across discovery, project provenance, design guidance, and package verification searches. Results overlap; this is a search-result count, not 85 independently reviewed libraries. Official project pages, package manifests, licenses, documentation, and published tarballs informed the selection.

**Select the Pajamas ecosystem for its documented interaction and visual foundations, and use selected GitLab SVG icons as build assets.** Preserve this project's independent visual identity and native controls. The full GitLab UI component runtime is a poor fit for this plain HTML/TypeScript application and this library's dependency-free core. This is a selection for our constraints, not a universal ranking of web UI libraries.

## What qualified

A candidate needs an identifiable project-owned GitLab repository, an inspectable license, a documented integration path, and useful implementation or interaction guidance. Compare semantic states and keyboard behavior, framework requirements, scoped styling, maintenance evidence, and suitability for a restrained glass control layer. Stars and polished screenshots alone do not establish these properties.

## Package inspection and adoption boundaries

The npm registry and release tarballs were checked directly, rather than relying on search snippets. `@gitlab/ui@138.4.0` was published on 9 October 2026. It contains `src/tokens/build/css/tokens.css` (138,895 bytes), `tokens.dark.css` (138,541 bytes), and JSON/SCSS forms. Its package license is MIT, copyright GitLab Inc. `@gitlab/design-tokens` does **not** exist in the public npm registry at this review date; do not invent it in installation recipes. These byte counts describe source assets, not browser transfer or bundle benchmarks. [Primary registry metadata](https://registry.npmjs.org/%40gitlab%2Fui).

The full component package is not added as a material-library runtime dependency. The app now includes selected SVG paths from pinned build-only `@gitlab/svgs@3.166.0`, reproduced by `npm run icons` and attributed in [THIRD_PARTY.md](THIRD_PARTY.md). The homepage and listening-room controls use these assets. We adopted Pajamas design guidance; no upstream token CSS is copied. Keep the relevant MIT notice with copied material, record the original package version, and verify the resulting app actually uses each selected asset. Package pinning does not imply the complete upstream design system, component behavior, fonts, or accessibility certification is included. [SVG registry metadata](https://registry.npmjs.org/%40gitlab%2Fsvgs).

## What the research changes in our design

- Start from a coherent real task and useful content. Present advanced material settings after the user has a useful default; omit decorative dashboards, fictional success metrics, and filler actions. Pajamas describes this as maintaining workflow continuity and revealing complexity progressively. [Principles](https://design.gitlab.com/get-started/principles).
- Assign tokens by meaning: reading text, supplementary text, focus, selected state, hover and pressed state. An accent color is not automatically a success or information state. Independent brand color and glass geometry remain ours. [Token guidance](https://design.gitlab.com/product-foundations/design-tokens-using).
- Use a small spacing vocabulary, with tighter distances inside a control and larger distances between sections. Use rem-based readable typography, a clear hierarchy, and restrained weight changes. This app need not reproduce GitLab's exact type sizes or typeface. [Spacing](https://design.gitlab.com/product-foundations/spacing), [type fundamentals](https://design.gitlab.com/product-foundations/type-fundamentals).
- Treat keyboard operation, visible focus, named icons, state announcements and contrast as acceptance criteria for each interaction. Adding a token or icon package does not implement those semantics. [Accessibility review guidance](https://design.gitlab.com/accessibility/best-practices).
- Use Liquid Glass for the small control layer above content. Keep reading surfaces solid, selected fills simple, and animation tied to an actual action. These material-specific choices are our design decision; they are not attributed to a component library that does not implement Liquid Glass.

Read [DESIGN.md](DESIGN.md) for the generation and review contract. Browser/device coverage belongs in [VALIDATION.md](VALIDATION.md); documentation review does not certify an upstream library or a physical phone.
